# ADR-0059: Tool 카세트를 제거한다

- 상태: 채택
- 날짜: 2026-08-22
- 담당: record, cli, dashboard
- 작성자: @ddxng5 (② replay/record 파트)
- 승인: 승인 (2026-08-22, @ddxng5 · ② replay/record 파트 오너가 검토하고 결정)
- 선행 결정:
  [ADR-0003](./0003-cassette-matching-key.md),
  [ADR-0051](./0051-external-record-replay와-tool-카세트-경계-분리.md)
- 참조: 구현 계획서 `docs/superpowers/plans/2026-08-21-external-record-replay-implementation.md` 단계 D

## 배경

[ADR-0051](./0051-external-record-replay와-tool-카세트-경계-분리.md)이 이 결정을 명시적으로
예약했다.

> 두 E2E와 CLI 배선이 모두 검증되기 전에는 legacy 코드를 삭제하지 않는다. 검증 후 최종
> 제품에서 Tool 카세트의 독립 가치가 없다고 판단하면 0.x breaking 변경으로 제거한다.

**그 전제가 충족됐다.** Record 수직 e2e 와 Replay 수직 e2e 가 모두 돌고
(`packages/cli/tests/external-session-e2e.test.ts`), CLI 배선은
[#249](https://github.com/2026-Engineering-Contest/MCPeak/pull/249)로 들어갔다. 그 뒤
[#265](https://github.com/2026-Engineering-Contest/MCPeak/pull/265)·[#267](https://github.com/2026-Engineering-Contest/MCPeak/pull/267)
이 사용자 보고 결함 둘을 닫으며 테스트를 더 두껍게 만들었다. 그러므로 지금 판단해야 할 것은
하나다 — **Tool 카세트에 독립 가치가 있는가.**

### 제거 대상의 실측 규모

| 자리 | 크기 |
|---|---|
| `packages/record/src/index.ts` (카세트 타입·매칭·IO·client wrapper) | 1,295줄 |
| `packages/cli/src/replay-command.ts` | 415줄 |
| `packages/cli/src/verify-command.ts` | 254줄 |
| `packages/cli/src/cassette-wiring.ts` | 92줄 |
| `packages/cli/src/generate-command.ts` 의 `--cassette`·`--record` | 46개 참조 |
| `packages/dashboard` (server 3파일 + web 6파일, `CassetteBrowser` 화면 포함) | 79개 참조 |
| 테스트 | 16개 파일 (핵심 5개만 124 케이스) |

**3개 패키지에 걸쳐 있고 오너가 갈린다.** 이 사실이 아래 실행 순서를 결정한다.

### `verify` 는 독립 기능이 아니다

판단이 갈릴 뻔한 자리라 따로 적는다. `mcpeak verify` 는 언뜻 카세트와 무관한 가치가 있어
보이지만, 그 명령이 존재하는 이유가 `packages/cli/src/verify-command.ts` 머리에 적혀 있다.

> 이 명령이 있는 이유는 `auto` 모드의 사각지대다. `auto` 는 히트하면 서버를 부르지 않으므로
> 서버 응답이 바뀌어도 영원히 모른다.

**`verify` 는 카세트가 만든 문제를 카세트 안에서 메우는 부속물이다.** 카세트가 사라지면 `auto`
모드가 사라지고, `auto` 가 사라지면 검증할 드리프트도 사라진다. 그러므로 `verify` 는 "제거하면
잃는 독립 능력" 이 아니라 **제거 대상과 함께 소멸하는 것**이다.

다만 드리프트 문제 **자체**는 External 세션으로 그대로 옮겨간다 — 석 달 전에 녹화한 세션도
원본 API 가 바뀐 뒤 그대로 재생된다. ADR-0051 이 이미 그것을 범위 밖·미정으로 남겨 두었고,
이 ADR 도 해결하지 않는다. 「결과」에 후속 과제로 적는다.

## 선택지

- **A안**: 유지한다. External 과 카세트를 둘 다 제품 기능으로 유지한다.
- **B안**: 개명한다. 이름만 바꿔 두 "녹화·재생" 의 혼동을 줄인다.
- **C안**: 제거한다. 사용자 표면부터 걷어내고 구현까지 지운다.
- **D안**: 사용자 표면만 걷고 내부 구현은 남긴다(`generate` dry-run 가속 용도로).

## 결정

**C안 — 제거한다.** 다만 아래 순서와 제약을 지킨다.

1. **제거 순서**(각각 별도 PR — ADR-0051 D-2).
   1. 사용자 표면: `mcpeak replay`, `mcpeak verify`, `generate --cassette`·`--record`,
      dashboard 카세트 화면
   2. 배선: `packages/cli/src/cassette-wiring.ts`, dashboard 의 `files.ts`·`routes.ts`·`wiring.ts`
   3. 구현: `packages/record/src/index.ts` 의 카세트 부분
2. **실행은 오너 경계로 조각내고, 자기 소유로 완주할 수 있는 조각부터 한다.**
   *(2026-08-22 개정 — 처음에는 "동결 전에는 실행하지 않는다" 였다. 위험 분석은 그대로
   유효하나, 그 위험이 조각마다 다르다는 것이 실측으로 드러나 아래와 같이 바꾼다.)*

   | 조각 | 참조 범위 | 단독 완주 |
   |---|---|---|
   | `mcpeak verify` | `cli` 안에서 닫힌다. `commands.ts` 재export 도 없다 | 가능 |
   | `mcpeak replay` | `commands.ts` **공개 재export** + dashboard 의 `wiring.ts`·`CassetteBrowser` 화면·`api-types`·`routes` | dashboard 동반 필요 |
   | `generate --cassette`·`--record` | ① 파트 소유 서브커맨드 | 해당 오너만 |
   | `record` 구현 | 위가 모두 걷힌 뒤에만 | 선행 조각에 묶임 |

   닫힌 조각을 먼저 걷는다. 남의 코드를 기다리며 중간 상태로 멈추지 않는 것이 기준이다.
3. **다른 오너의 패키지는 그 오너가 걷는다.** `record` 는 `@ddxng5`, `dashboard` 는 공동,
   `cli` 의 각 서브커맨드는 그 파트 담당이 맡는다(`CLAUDE.md` 패키지 경계 규칙).
4. **0.x breaking 으로 낸다.** changeset 과 마이그레이션 안내를 반드시 동반한다
   (CONTRIBUTING §7 — 0.x 는 breaking 을 허용하되 CHANGELOG 에 남긴다).
5. **External 기능 추가와 legacy 삭제를 같은 PR 에 섞지 않는다**(ADR-0051 D-4 재확인).

## 이유

**독립 가치가 없다고 판단한 근거는 세 가지다.**

첫째, **겨냥하는 문제가 External 에 흡수됐다.** 카세트는 *우리가 서버에게 물어본 것* 을 남겨
서버를 다시 띄우지 않게 한다. External 세션은 *그 서버가 밖에 물어본 것* 을 남기고 **서버는
실제로 띄운다.** 서버를 실행하지 않는 재생은 "이 서버가 정말 그렇게 동작하는가" 를 증명하지
못한다 — 테스트 도구로서 더 약한 보장이다. ADR-0051 이 "새 결정의 핵심은 실제 MCP 서버 코드를
Replay 에서도 실행하는 것" 이라고 적은 것이 이 차이다.

둘째, **남는 용도는 이미 다른 패키지의 책임이다.** "실제 서버 없이 테스트한다" 는 ADR-0051 이
명시적으로 `mock` 에 맡긴 장기 책임이고(「실제 MCP 서버를 대신하는 장기 책임은 `mock`에 있다」),
`mock` 은 그것을 사람이 지정한 결정론적 응답으로 한다 — 낡을 수 있는 녹화본보다 그 용도에 더
맞는다.

셋째, **두 개를 유지하는 비용이 영구적이다.** ADR-0051 이 이 비용을 이미 값매김해 두었다.

> 일시적인 중복보다 영구적인 의미 혼합이 더 큰 비용이다.

실제로 그 비용을 이번에 치렀다. `packages/record/README.md` 에 "이 둘이 어떻게 다른가" 표를
넣어야 했고, `mcpeak help test` 도 같은 구분을 다시 설명한다. 사용자가 매번 배워야 하는 구분은
제품이 지고 있는 세금이다.

**B안(개명)을 버린 이유는 문제가 이름이 아니기 때문이다.** 이름을 바꿔도 사용자는 여전히 두
녹화 개념 중 하나를 골라야 하고, 우리는 여전히 두 구현을 유지한다. 혼동은 줄지만 비용은 그대로다.

**D안(구현만 남기기)을 버린 이유는 그것이 가장 나쁜 조합이기 때문이다.** 공개 표면이 없는 1,295줄을
유지하면 아무도 쓰지 않는 코드에 테스트·타입체크·리팩터링 비용을 계속 낸다. `generate` dry-run
가속은 실측된 요구가 아니라 추정이며, 필요가 확인되면 그때 External 이나 `mock` 위에서 다시 만든다.

**실행을 한 번에 하지 않는 이유는 위험이 조각마다 다르기 때문이다.** 제거 전체는 3개 패키지·
여러 오너의 코드를 건드리고 124개 이상의 테스트를 걷어낸다. 동결까지 이틀 남은 시점에 그것을
통째로 하면 되돌릴 여유가 없고, `CLAUDE.md` 의 패키지 경계 규칙상 다른 오너의 승인·작업을
동시에 받아야 한다.

그러나 그 위험은 조각마다 다르다. `mcpeak verify` 는 `cli` 안에서 닫혀 있어 — `commands.ts`
재export 도 없고 dashboard 도 부르지 않는다 — 혼자서 끝까지 걷을 수 있다. 반면 `mcpeak replay`
는 공개 재export 면에 있고 dashboard 가 실제로 부른다. **닫힌 조각을 미루는 것은 안전이 아니라
지연이고, 열린 조각을 서두르는 것이 진짜 위험이다.** 그래서 기준을 시점이 아니라 경계로 잡는다 —
남의 코드를 기다리며 중간 상태로 멈추지 않는 조각만 지금 한다.

## 결과

- **진행 상황**(조각이 나갈 때마다 갱신한다 — 계획과 실제를 함께 남긴다).

  | 대상 | 상태 |
  |---|---|
  | `mcpeak verify` | **제거 완료** (2026-08-22, PR #275). 실행하면 제거 사실과 갈아탈 곳을 안내한다 |
  | dashboard 카세트 화면·replay 플로우 | **제거 완료** (2026-08-22, PR #282). `CassetteBrowser`·`wiring.ts` 의 카세트 경로가 사라졌다 |
  | `mcpeak replay` | **제거 완료** (2026-08-22, PR #283). `verify` 와 같은 마이그레이션 안내를 낸다 |
  | `generate --cassette`·`--record` | 제거 예정. ① 파트 소유라 그 오너가 걷는다. **남은 유일한 사용자 표면이다** |
  | `cli/src/cassette-wiring.ts` | 제거 예정. `generate` 가 걷힌 뒤 — `@mcpeak/record` 메인 진입점의 마지막 import 지점이다 |
  | `record` 의 `verifyCassette` | **라이브러리로 유지 중.** CLI 진입점만 사라졌고, 구현 제거는 표면이 모두 걷힌 뒤다 |
  | `record/src/index.ts` 카세트 구현 | 제거 예정. 위 표면이 모두 걷힌 뒤에만. 외부 소비자는 `cassette-wiring.ts` 와 `generate-command.ts` 둘뿐이다(2026-08-23 실측) |

  제거 전까지 남은 명령에 새 기능을 얹지 않는다.
- **`record` 는 최종적으로 External 전용 패키지가 된다.** 패키지 설명·README·`exports` 를 그때
  다시 정리한다. 지금 `packages/record/README.md` 가 카세트를 "legacy 이고 제거 예정" 으로
  적어 둔 것이 이 결정과 일치한다.
- **External 세션의 드리프트 재검증 수단이 없다.** `verify` 가 카세트에 대해 하던 일의 External
  판이 없으며, 이 ADR 은 그것을 만들지 않는다. 녹화가 낡는 문제는 그대로 남는다 — **별도 ADR
  대상이다.** 카세트를 걷기 전에 이 후속을 결정할지, 걷은 뒤에 할지는 실행 시점에 정한다.
- 발행본(`@mcpeak/cli` 0.9.0, `@mcpeak/record` 0.2.0)에 이미 이 명령들이 나가 있다. 제거
  릴리스에는 "무엇이 사라졌고 무엇으로 대체하는가" 를 적은 마이그레이션 안내가 따라야 한다.
  대체 경로는 용도에 따라 갈린다 — 외부 API 를 막고 싶으면 External 세션, 서버 자체를 대신하고
  싶으면 `mock`.
- CI 의 자체 검증 E2E(`examples/` 예제 서버)는 카세트를 쓰지 않는다. 제거가 "우리 도구로 우리를
  검증한다" 를 깨지 않는다는 것을 확인했다.
- 이 결정이 뒤집히려면 카세트만 할 수 있는 사용자 요구가 실측돼야 한다. 추정이 아니라 보고된
  사용 사례여야 한다.
